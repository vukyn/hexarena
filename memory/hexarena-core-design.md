New standalone Go repo `hexarena` (module `github.com/vukyn/hexarena`), started 2026-08-24. Turn-based PvE team battler, terminal-first then ebiten GUI. Not a platform service: no DB/DI/domains/clean-arch/kuery/mprocs — like [[sgo-onboarded]] / speedtest.

Decisions locked with the user (do not re-litigate):

- **Turn order = ATB / action value**, `av = 10000/speed`, min-heap timeline, tie-break by unit id. Explicitly rejected simple per-round speed sort (kills speed buffs + double-turns).
- **Board = ONE shared odd-q offset hex grid, 6 cols x 3 rows.** c0-c2 ally (c2 = frontline), c3-c5 enemy (c3 = frontline). Team authors its own 3x3 (col 0 = own back, col 2 = own front); `Place()` maps enemy via **180° rotation** — without it the two halves are NOT mirror-symmetric because odd columns are pushed down, and balance drifts silently. Max team 5 of 9 slots.
- ⚠️ **Reach is RANKS from the far side, not cells from the caster** (PR #133/#134, 2026-08-28). Range N reaches the first N **occupied** columns of the enemy half, counted from *their* frontline; an empty column costs nothing. **Blocking is by the whole rank** — one unit anywhere in a column shields every column behind it. Ally-aimed skills **ignore range entirely**; a **taunt pierces** blocking (`aims` returns taunters before reach is consulted). `maxRange` = `hex.FormationCols` = 3. *Why:* units never move and most skills are range 1, so measuring from the caster's own cell made a back-line placement unable to use its own kit. The old ladder (1 = front↔front, 2 = mid, 3 = back, max 5) is **dead** — do not quote it.
- ⚠️ **Consequences that bit:** a board can no longer freeze for want of distance, so the reach guard in `battle.New` + `canAimAtAnyone`/`longestRange`/`nearestTargetable` were **deleted as unreachable**; `Stalemate` survives only for "no kit holds anything to throw", and the whole draw test family was restaged on that. The caster's own column is now **purely defensive**, and rows affect only pattern shapes. `TestNoPlacementCanPutAUnitOutOfReach` stops the guard being re-added.
- ⚠️ **The NUMBERS turned blocking on, not the mechanism.** #133 shipped with old ranges where most skills were depth 2–3 and walked round a held rank; #134 put 14 of 31 at depth 1 and the front rank started deciding fights. Cost: instrument 19/40 → **12/40 ally**. Diagnosed as **placement**, not kits — both sides lost depth evenly, and `hydro_pump` (only depth-3 skill, enemy-only) is provably not the driver. Re-levelling `roster.json` is the open follow-up.
- Square 3x3 was considered and **rejected**: Chebyshev makes rows cosmetic from dcol>=2, Manhattan makes adjacent-but-offset melee unreachable.
- **Element chart = 2 four-cycles + a cross 8-cycle**, so all 8 cycled elements have exactly 2 strengths / 2 weaknesses. organic `water>fire>grass>ground>`; industrial `ice>metal>wind>electric>`; cross `water>metal>grass>wind>fire>ice>ground>electric>`. Plus `light<>dark` mutual dyad and inert `neutral` = 11 total. light/dark being x1 vs everything else is accepted because this is PvE (designer controls enemy comps).
- **Skills/passives are data**: effect list + trigger hooks in JSON, interpreter in Go. Never one Go type per skill.
- ⚠️ **`TODO.md` at the repo root is where "what is left" lives now** (PR #122). It is an *index*: one line per open item plus a pointer into `CLAUDE.md` § Open work or `README.md` § Roadmap, which hold the reasoning. **Tick it in the same commit as the work** — it is the one hand-kept file in a repo where everything else is derived, so it is the only thing here that can quietly go stale. It also carries a "decided against — do not re-raise" section (`at_stage`, a character class, a dependency ban).
- **Engine is integer-only and pure**: no floats, no `time`, no global rand, no map iteration in output paths, no filesystem in core. Element multipliers are parts-per-thousand ints (advantage 1500 / neutral 1000 / disadvantage 667), damage scales via `dmg*mult/1000`. This is what makes a battle replayable from `(seed, teams)` — same discipline as [[worldbit-plan]].
- Core emits `[]Event`; terminal CLI and ebiten both replay that same stream. GUI is a pure renderer.
- **Milestone 1 = interactive CLI** (player picks skill + target at the prompt), not headless auto-battle.
- `Line`/`Cone` hex shapes deliberately NOT implemented — the standard algorithm needs float lerp + cube_round. Add an integer-only version when a skill actually needs it.

**SHIPPED 2026-08-24.** Private repo `git@github.com:vukyn/hexarena.git`, 3 commits on main, pushed. 14 packages, 230 tests, ~14.3k LOC. **No longer stdlib-only**: the user ruled on 2026-08-25 that third-party libraries are fine anywhere in the module (bubbletea/bubbles/lipgloss arrived with the authoring TUI, first go.sum). Do not re-impose a dependency ban — the layer rule that survives is purity, not stdlib: `internal/core` stays a pure function of its integer arguments so a battle replays from its seed. See [[hexarena-cast-authoring]]. `README.md` + `CLAUDE.md` written; the repo's own CLAUDE.md carries the layer rule and a "Mistakes already made here" list.

Packages: `scale` (saturation + permille) · `rng` (splitmix64, the ONLY randomness) · `hex` · `pattern` (6 named dirs + 9 AoE shapes) · `element` · `combat` · `progression` · `modifier` · `status` · `atb` · `skill` · `battle` (the ONLY state) · `seed` (8 embedded json) · `tui`, plus `cmd/hexarena`.

**Non-obvious footgun:** `-update` for goldens is declared only in `internal/core/hex`, `internal/seed`, `internal/tui`, so `go test ./... -update` FAILS on every other package. Correct form is `go test ./internal/core/hex ./internal/seed ./internal/tui -update`; a new golden-owning package must be added by hand.

**Verifiable logs.** `--log` writes seed + decisions + events; `--replay --verify` re-runs from the seed and diffs every event. That check found 2 real defects on first run: a pass reason worded differently by two code paths, and Replay not walking the forced turns after the last decision. Undo needs no snapshot — drop the last own decision and replay the rest.

**Ordering bugs already fixed inside battle.Advance**, each earned by a failing test: check control BEFORE spending durations, else a 1-turn stun expires in the turn it should block · retune EVERY unit after any stat change, not only the acting one, else a self-haste never shortens the wait it is about to serve · spend cooldowns at turn END, else the offered options and the allowed action read different numbers and a cooldown of 3 costs only 2 turns.

Still open (in the repo's README Roadmap + CLAUDE.md): ebiten client, asset pipeline undecided since ebiten draws no SVG · **battle.Suggest is shallow — never buffs, cleanses, shields or sets up a detonate, so the whole timed-effect layer is tested but not played** · real cast using progression.Line evolution stages, which nothing uses yet.

**Healing SHIPPED (2026-08-25), piercing SHIPPED (2026-08-26).** Both had their README/CLAUDE.md open-work entries removed and rewritten as body sections + invariants — the healing commits had shipped without touching docs, so both files claimed "nothing restores health" for a day.

**Healing = three separate mechanisms**, one rule each that must not be undone: skill `restores` · skill `drains` (reads `combat.DamageDealt`, NOT the damage rolled) · `regen` status. `combat.Rules.Restore` **deliberately does not divide by the defence curve** even though a DoT tick does — defence turns away harm, not help; do not add the division for symmetry. `status.Set.Tick` returns **two unsigned totals** (damage, healing), never one signed number: a negative down the damage path would subtract a negative and `wound` calls `kill` at zero, so a signed total is the one shape that could revive a corpse. Dead is not healable, health clamps at MaxHP, every restore emits `Healed`.

**Piercing = `skill.Skill.Pierce`, permille of defence ignored, applied by `combat.Pierced` inside `Rules.Strike`.** Ratio not switch, as measured (0.98x → 1.55x). Three decisions locked:
- **It stops at the strike.** A DoT tick applied by a piercing skill uses FULL defence. A tick is frozen at application, so piercing it is worth as many pierced hits as the stack has turns left — measured 400/turn × 3 turns vs 171. `battle.inflict` passes raw defence deliberately; a test bites if that changes.
- **`Rules.Damage` knows nothing about piercing** — it takes the defence *as it applies*. README had proposed a 5th positional param; rejected because five positional ints pass a mis-ordered argument silently, and a caller reaching `Damage` directly wants the raw curve (which is what the frozen tick needs).
- **The `Damaged` event carries `Pierce`**, and the tui reads it out (`through 40% of the armour`). Without it a reader cannot reproduce the figure.
`progression.EffectiveHP` now describes ONE case of two → `EffectiveHPAgainst(values, rules, pierce)`; fully pierced == raw hp. Both tools show both figures: the budget meter keeps its line and the pierced floor goes on the row **underneath** — at the 79-cell floor the clause does not fit on the line at any readable wording, and neither a shorter meter nor an unlabelled number is worth the row.
**`razor_leaf` carries the only non-zero pierce, 400** (2026-08-26). Payoff curve is the whole justification: +0% vs 0 defence, +11% vs 100, +29% vs 400, **+41% vs the 800 ceiling**. Does not warp the kit — over 40 auto-battles it goes 34% → 37% of casts. ⚠️ **The shipped roster is a MIRROR (both squads same kit), so win-rate is NOT a balance signal** — piercing helps both sides equally; judging the number needs an asymmetric roster.

**Raw hp needs NO floor, and that was measured not decided.** A *ratio* floor (raw hp as share of effective hp) is algebraically `DefenseReduction(defence)` — depends on defence alone — so it **IS** the defence ceiling already at 800; not a new knob. An *absolute* floor cannot work: `CheckTable` walks levels 1..60 and every unit's hp is small at level 1. And unneeded: among budget-saturating lines raw hp runs 3128 (def 800) → 4800, a **1.53x** edge fully pierced, vs the **2.25x** the worst elemental matchup already swings. If it ever bites, turn `ceilings.defense`.

**Per-stage art SHIPPED (2026-08-26).** `progression.Stage.Image` optional; **`cast.Character.StageArt` is the ONLY place the fallback to `Character.Image` is decided** — read `Stage.Image` directly and the ordinary stage draws nothing. Lives in `progression` beside `Name` (facts about the form, not rules); path checked by `cast.ValidateImagePath` per stage at parse time, **only when non-empty** (it refuses `""`). A character has a **set** of pictures: `Character.Art()` = distinct by path, declaration order, character's own first — `Library.Inspect` walks all of them, `CharacterReport.Art []ArtReport` replaced `Image`/`ImageExists`. Shipped: bulbasaur stage names none (exercises the fallback), ivysaur/venusaur have their own. **Assets are NOT go:embed'd** (only JSON is), so SVG size never reaches the binary. Art conversion = `python3 img2svg/cli/img2svg.py <png> -o <svg> -q faithful` (matches bulbasaur.svg); rasterise back with `qlmanage -t -s 400 -o <dir> <svg>` to eyeball before committing. Raster sources are **deleted** — SVG only in the repo.

**Art preview SHIPPED (2026-08-26).** `p` from the TUI browser → `screenPreview`, draws the form the level resolved to; keeps **no cursor/level of its own** (reads `m.browse`). `forge.ArtImage` is the **only** rasteriser in the repo (oksvg+rasterx, the pair README already named) and returns **pixels only** — never characters, never flattened alpha. Two pixel rows per cell as `▀` half-block (cell ≈ square, no font correction). Go RGBA is **premultiplied** → un-premultiply before use or colour is wrong over any non-black terminal bg. Alpha floor deliberately **low** (40): traced vector's in-between pixels ARE its outlines. `MaxArtPixels` caps a side (cost ∝ area, redraws per keystroke). **This is the ONE place colour = information**, so the NO_COLOR path is a *different drawing* (ASCII ramp keeps shading) not the same one decoloured. **Cache keyed on file size+mtime, never path alone** — two earlier test designs proved nothing: counting map entries (cacheless writes same key) and deleting the file (froze wrong behaviour); now measured by chmod 0 with size/mtime unchanged. **Cast art must be a CUT-OUT, never framed** — a unit stands on a board, so a baked background is always wrong. bulbasaur.svg originally carried one (first path = full-canvas rect, traced from an alpha-less PNG): 92% of the box inked vs ~36% for the others. Retraced 2026-08-26 from an alpha PNG → 630×630, 410KB. Guarded by `TestTheShippedArtIsCutOutRatherThanFramed`. ⚠️ **It measures the corners of the INKED rectangle, not of the box** — a square box letterboxes non-square art, so box corners are transparent margin and a framed asset passes clean (my first version did exactly that). Always check a source PNG has a `tRNS`/alpha channel before tracing.

**Passives SHIPPED (2026-08-26), 1 of 4 jobs.** `internal/core/passive` — a trait grants **status ids only**; terms live on the status so it saturates *alongside* temp buffs via `modifier.Set` (composing = the one place stacking explodes). Granted statuses MUST be `permanent: true` on `status.Kind` (**a flag, NOT duration 0** — 0 would make a mistyped duration silently permanent). Permanent = 4 things: never ticks down · `Set.Remove` refuses it (one guard covering dispel+cleanse+detonate, because a trait is granted ONCE) · cannot be Dot/Regen · `Snapshot.Permanent` so renderers draw "always" not "0t".

⚠️ **THE trap: `enlist` grants BEFORE `queue.Add`** and adds at `b.Stats(unit)` speed — wait = 1e6/speed and the first wait is already served by the time `retuneAll` would fix it. **My first test used two EQUAL speeds and passed the mutation** (holder won the tie-break either way); must make the holder SLOWER at base and faster only with the trait (100 vs 130 → 145 vs 130). Events emitted in `Begin`, not `enlist` (no log exists before the opening board). New kind `passive_held` (own kind, not `status_applied` with empty skill). `battle.Roster.Passives` — first roster field that is neither stat nor skill; the test is "does a replay read it", not "is it small".

Shipped: `blighter` **suggests** `endurance` (archetype's first mechanical weight ever) → Bulbasaur takes it; golden 43→37 turns, survivor 140→1354hp (mirror roster = hint, not measurement). `hexforge passives` lists the book.

**Two bugs the tests found:** (1) a **health modifier on a status has always done nothing** — `Unit.MaxHP` reads the BASE line — now refused at parse, because fixing it needs a decision about current-hp following a moving max; (2) `recheckCarriers` **restated its dependency lists**, so every skill edit broke the moment passives existed → now uses `Library.ArchetypeDeps()`/`CastDeps()` and swaps only the skill book. **Never restate a deps list.**

**Trait unlock = the SAME mechanism as the skill learnset, never a second one** (design noted 2026-08-26, not built): one `{id, at_level}` shape + one validator + one availability fn, used by a kit with 4 slots and a trait list with **1**. ⚠️ **`at_stage` cannot be built before chosen evolution** — `Line.StageAt` derives stage from level today, so `at_stage:"Ivysaur"` *is* `at_level:16`. **Gating is separable from slots and far cheaper**: gate + bring-all-unlocked is not a choice → no log change; a slot IS a choice and `battle.Log` = seed+choices+events only (roster comes from embed), so a chosen loadout must go INTO the log or `--verify` compares two different battles. **Build order: (1) gate traits (2) the 3 missing passive jobs (3) slots + log placement.** Step 2 is middle on purpose: a slot between three stat traits is not a decision.

Still open (3 jobs): extra applications (`skill.Application` assembled from unit+skill) · conditions (`skill.Condition` **cannot** say "holder below a share of health" — that term IS the work). **Health thresholds SHIPPED (PR #56).** `skill.Condition.BelowHealth` (permille) reads the **target**; `passive.Condition` reads its **holder**; `brine` moved onto it and is its canon move (1000→2000 power at ≤50%). ⚠️ **They share the arithmetic (`scale.AtOrBelowShare`), NOT the type** — one Condition could not say *whose* health it meant, and `passive` imports `skill` so the shortcut was unwritable anyway. A condition reads a status, health, or both, and **both is AND** (a clause narrows, never widens). Reading is a **`skill.Target`** struct (stacks/health/maximum), not three params — two int64 healths swap silently. ⚠️ **`battle.conditionTarget` is the single builder** shared by `Suggest` and `resolveAgainst`; separate readings would make the AI prefer a bonus it never gets. A *gradient* (harder the further the **caster** fell) is still unbuilt: multiplier in `combat`, reads the other unit, separate feature. · **resistance** — choke point is `battle.inflict` where the chance is rolled, NOT `Set.Apply`; a ratio reducing a chance saturates, refusing outright is a hard cap on a continuous quantity; declared 1000 = explicit immunity, mirroring accuracy 1000.

**Two goldens could not explain their own numbers**, both found by that one line of data, not by the mechanism: `skills.golden`'s damage column built a `Hit` with no `Pierce` (reported 410 while the game dealt 532 — design record contradicting the design), and `replay.golden`'s damage line said nothing. Both now carry the share. **Lesson: when a mechanism reaches the data, re-check every generator that recomputes damage.**

**BUG FIXED (pre-existing):** `hexforge skills edit --self-applies/--restores/--drains` **never worked** — two maps keyed by the same flag names, three flags added to one only; a missing key reads back nil = "flag not given", so it answered `nothing to change` and wrote nothing. Now one table per flag carrying both halves. Test reads the flag list out of the command's own `-h` so it cannot drift.

**A near-equivalent already exists:** DoT reads the target's defence at *application* time and freezes it, so `expose` (defence debuff) applied **before** a poison permanently strengthens every stack, even after expose lapses. Lower the defence rather than ignore it. `battle.Suggest` never plays it.

**TRAIT LAYER COMPLETE (2026-08-26/27).** All five passive jobs plus slots shipped in one burst: gated grant (#62) · amplify a status (#65) · answering back (#67) · passive lifesteal (#66) · learnset + slots (#70). `SkillSlots=4`, `TraitSlots=1`, a placement **must** choose (no default — a default would pick four of nine and never say which). ⚠️ **A trait slot is only a decision once traits differ in KIND, not number** — Bulbasaur's five traits are four kinds (resist+reply, amplifier, stat change, drain, gated drain), which is what makes its two builds (poison vs Vladimir-sustain) real alternatives; `TestBulbasaurCanBeBuiltTwoWays` fails if `TraitSlots` grows or a direction loses its last entry. ⚠️ **A gated share is cheaper than a gated grant, not more legal** — a share is read fresh per strike (no `Hold`/`Release`, no event either way, no retune); both are writable. ⚠️ Trait drains **add** and cap at `scale.Base` — a *conservation* (cannot take back more than dealt), not the buff ceiling this engine rejects; saturating pays 285 for a trait that says 400. ⚠️ The `Healed` event carries **`Drained`** — the `Pierce`/`Refused` trap again: a number a reader cannot reproduce needs its share on the event. See [[hexarena-descriptions-are-derived]] for the description layer that reads all of it.

**DAMAGE NUMERATOR TRÀN `int64` — SỬA #180.** `Rules.damage` nhân **năm** thừa số (attack · skill · affinity · crit · `DefenseConstant`) rồi mới chia; ở `int64` nó **tràn câm**. Nguy hiểm KHÔNG phải mấy giá trị sập về `MinimumDamage` (thấy ngay) mà là `power 90,000,000 → 4,504,651`: số to, hợp lý, **sai** — và biểu thức **không đơn điệu theo power**, nên không bản đọc đơn lẻ nào phát hiện được. ⚠️ **"Chia sớm hơn" BỊ CẤM**: package doc dựng trên *một* phép chia, và cơ chế crit dựa thẳng lên `floor(1000a/1000b) == floor(a/b)` — đó là lý do thêm crit không dịch một con số nào. Cắt hai lần = dịch mọi golden. Fix = **nới chỗ nhân lên 128 bit** (`wide{high,low,exact}` + `math/bits`, stdlib nên không phạm luật layer), chia vẫn một lần, kết quả **giống hệt từng bit** dưới ngưỡng tràn cũ.

⚠️ **`bits.Div64` PANIC** khi divisor 0 hoặc thương vượt 64 bit — panic trong công thức sát thương tệ hơn cái tràn nó thay. Guard hoá ra **một** so sánh: tiền điều kiện là `high < divisor`, mà `high` unsigned nên divisor 0 rớt luôn. Mệnh đề `denominator == 0` riêng được **mutation chứng minh là thừa (xoá vẫn xanh, 2 lần)** — đó là cách chứng minh một guard thừa, không phải suy luận. Bão hoà `math.MaxInt64` là chặn **KIỂU** không phải chặn thiết kế (`max_effective_hp` 11,500 → chạm guard là đã giết sạch), và là lựa chọn duy nhất giữ được tính đơn điệu.

⚠️ **Trần cho `Skill.Power`: QUYẾT ĐỊNH KHÔNG ĐẶT** (TODO § Decided against). Đo ở tổ hợp xấu nhất chạm tới được (atk 2399 bão hoà, affinity 2000, crit 1250, K 300): cũ giữ tới **5,126,231**, mới tới **1.54e18**, sách hiện tại **2,400**. **Một giới hạn kỹ thuật không được đóng vai một ranh giới thiết kế** — đúng phân biệt mà chính sách stat-bounds dựa vào (xem [[hexarena-stat-bounds-policy]]). Trần chống lỗi đánh máy là tính năng KHÁC, lý do khác, phải nêu riêng.

CÙNG HỌ, CHƯA SỬA: mẫu số `1000³×(K+def)` cũng tràn `int64` (và về đúng 0 khi tổng là bội 2⁵⁵) — `Validate` không chặn trên `DefenseConstant`; không chạm tới qua data ship (tổng lớn nhất 2,699). Và `combat.Swung` tính trong kiểu `int`, tràn quanh 9.2e15 — nó chính là giá trị **trở thành** `skillMultiplier`.
